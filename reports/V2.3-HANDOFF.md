## What V2.3 does

Capture used to be bound to one repo, and the shared companion files were
global, so opening a session in repo A injected repo B's `Last-Session.md`.
V2.3 makes *operational continuity* per-project while keeping *learned
knowledge* shared across the Pikselzone workspace.

- `memory_v1/project_registry.py` — authority record at
  `<state_path>/registry/projects.json`. Never infers a project at runtime; it
  only authorises the identity the hook carries. One project may own many roots.
- Single authority rule: capture is ON only when the hook's `--project` /
  `--project-root` exactly match a registry entry AND the runtime cwd is inside
  that root. Everything else fails closed.
- `memory register <root> --project <slug>` installs five hooks
  (SessionStart, SessionEnd, PreCompact, Stop, UserPromptSubmit) into the repo's
  `.claude/settings.local.json` and `.codex/hooks.json`, non-destructively.
- `continuity_scope` (which continuity file) is separate from `project`
  (event provenance). Hermes: scope `hermes`, provenance `unscoped`.
- Startup Tier D (recent daily tail) is filtered to the current project;
  cross-project *knowledge* transfer happens only in associative recall.
- `associative_recall_fast` — synchronous UserPromptSubmit hook, index-first,
  ≤3 concept reads, no graph traversal, fail-open.

## The sync-conflict root cause (fixed)

All 23 `(Conflicted copy pz-hermes ...)` files came from `index.md` and
`log.md` having two independent whole-file writers on two hosts. The LLM
compiler regenerated both wholesale each run (different heading and row count
every time), while the workstation graph engine rewrote them on every flush.
Obsidian Sync cannot merge two divergent full-file rewrites.

`pz-obsidian-sync.service` is a pure sync client and was never the mutator.
Sync topology was not changed.

Now: the model may propose only `concepts/**` and `connections/**`;
`memory_v1/knowledge_index.py` owns `index.md` (deterministic rebuild from
concept frontmatter) and `log.md` (generated audit line) after a successful
promotion. `EventWriter.flush`, `publisher.publish_outbox`, parity alignment
and the importer no longer touch `knowledge/` at all.
