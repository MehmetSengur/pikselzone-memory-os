## Onboarding disiplini — register ≠ geçmiş içe aktarımı

`memory register` **gelecekteki** native capture'ı açar. Eski proje dosyalarını
otomatik olarak shared knowledge'a **dönüştürmez**. Historical intake için tek
doğru hat:

```
MEMORY_INTAKE.md → gerçek registered project session → daily/ → VPS compiler → knowledge/
```

## `knowledge/` single-writer kuralı

`knowledge/` **compiler-owned**. Canonical writer VPS compiler'dır;
Claude/Codex/Hermes session flush graph'ı doğrudan mutate etmez ve
**`knowledge/` içine elle yazılmaz**. `index.md` ve `log.md` concept
frontmatter'ından deterministik üretilir; LLM compiler bunları yazamaz.
(2026-08-30'daki 23 sync conflict'inin kök nedeni buydu; çözüldü.)

## Orchestrator çalışma modeli

`pikselzone-orchestrator` nötr genel danışma alanıdır: başka projelerin
last-session continuity'sini **taşımaz**, shared knowledge'ı **kullanır**,
güncel operational truth gerekiyorsa ilgili **project root'una dönülür**.
